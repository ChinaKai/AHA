## L3：自愈与监督（看门狗）【已完成 2026-08-15】

目标：卡死 backend 自动识别重启，不依赖用户手动 reset session。

- [x] `services/agent_watchdog.py`：`stuck_agent_reason` 检测「backend 状态 running（进程活着）但 inbox 有待处理消息且超过 `WATCHDOG_STUCK_SECONDS` 无活动」→ 判定卡死；`recover_stuck_agent` 强制 stop + restart，**保留 chat cursor 不清 pending 消息**（区别于 `record_agent_interrupt` 的推进 offset 语义）
- [x] `scan_run`/`scan_all_runs`：周期扫描 active runs 的 running agents，单 agent 每扫描限 `WATCHDOG_MAX_RESTARTS_PER_SCAN` 次、`WATCHDOG_MIN_RESTART_INTERVAL_SECONDS` 防恢复风暴
- [x] busy backend（有 `agent_started` 无 `agent_finished`）不误伤；agent 非 running 不处理
- [x] Web server 接入 `agent_watchdog_loop`（`WATCHDOG_RECONCILE_SECONDS = 20`），随 UI server 生命周期启停
- [x] 测试：`tests/test_agent_watchdog.py` 7 个用例（检测/不误伤/恢复保 cursor/最小间隔/全 run 扫描）
- [x] 相关回归：test_web_status + test_chat_offsets + test_agent_watchdog 全过

> 说明：现有 `recover_stale_running_agents` 只处理「backend 进程已死（stopped）」；L3 补齐「backend 进程活着但不消费 inbox」的卡死场景，二者互补。
